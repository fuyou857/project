## 一、测试背景与目标

### 1.1 测试背景

本次测试源于用户反馈的成本发票录入模块中模态框交互异常问题。具体表现为：
- 点击取消按钮后，模态框无法正常关闭
- 遮罩层在关闭后仍然停留在页面上
- 页面其他区域的交互被遮罩层拦截

### 1.2 测试目标

1. 定位并修复模态框关闭逻辑缺陷
2. 确保模态框及其遮罩层能够正确从DOM中移除
3. 验证取消按钮、ESC键、背部点击等多种关闭方式的正常工作
4. 确保修复不影响其他功能模块

### 4.2 关键问题根因分析

#### 问题P001-P003：模态框关闭后DOM残留

**问题现象**：
- 点击取消按钮后，`role="dialog"`元素仍然存在于DOM中
- 遮罩层虽然透明但仍然拦截页面点击
- body的pointer-events未恢复正常

**根因分析**：
1. 原始代码使用了`AnimatePresence`组件配合`exit`动画
2. 当`open`状态变为`false`时，组件立即返回`null`
3. 这导致`AnimatePresence`无法完成退出动画，元素滞留DOM中
4. 虽然`pointer-events: none`可以让元素不可点击，但元素仍在DOM中

**修复方案**：
```tsx
// 修复前
return createPortal(
  <AnimatePresence>
    {open ? (
      <motion.div>
        {/* ... */}
      </motion.div>
    ) : null}
  </AnimatePresence>,
  document.body
);

// 修复后
if (!open) {
  return createPortal(null, document.body);
}

return createPortal(
  <motion.div
    initial={{ opacity: 0 }}
    animate={{ opacity: 1 }}
    transition={{ duration: 0.18 }}
  >
    {/* ... */}
  </motion.div>,
  document.body
);
```

**修复效果**：移除了`AnimatePresence`和退出动画，只保留入场动画，确保React能立即从DOM中移除元素。

#### 问题P005：onClose回调闭包问题

**问题现象**：
`onClose` useCallback的依赖数组包含了整个`ocr`对象，每次渲染都会创建新的函数引用。

**修复方案**：
```tsx
// 修复前
const onClose = useCallback(() => {
  // 使用 ocr.ocrUiStatus
}, [ocr, ...其他依赖]);

// 修复后
const { ocrUiStatus, resetOcrMeta } = ocr;
const onClose = useCallback(() => {
  // 使用解构后的值
}, [ocrUiStatus, resetOcrMeta, ...其他依赖]);
```

**修复效果**：依赖项稳定，避免了不必要的函数重新创建。

## 五、测试经验与教训

### 5.1 成功经验

1. **自动化测试的价值**
   - E2E自动化测试能够快速发现交互类问题
   - 测试脚本中的状态检测函数（`readBodyInteractionState`）非常有效
   - 能够在短时间内执行多次迭代测试

2. **渐进式修复策略**
   - 从最简单的修改开始，逐步增加复杂度
   - 每次修改后都运行E2E测试验证效果
   - 避免了"一步到位"式的大规模重构风险

3. **测试环境隔离**
   - 使用Playwright的headless模式，避免浏览器环境差异
   - 固定的视口大小和配置确保测试可重复性

### 5.2 教训与反思

1. **对动画库行为的误解**
   - 最初认为`AnimatePresence`会自动处理退出动画
   - 实际上组件必须始终保持挂载才能执行退出动画
   - 需要深入理解库的内部机制，不能仅凭表面API使用

2. **过早优化的陷阱**
   - 最初保留了退出动画，希望保持用户体验
   - 但这种"优化"导致了功能缺陷
   - 应该优先保证功能正确，其次才是体验优化

3. **测试覆盖的重要性**
   - 如果没有E2E测试，这个问题可能不会被发现
   - 单元测试难以发现DOM交互类问题
   - 应该加强E2E测试用例的编写和维护

### 5.3 改进建议

1. **代码层面**
   - 为所有模态框组件编写集成测试
   - 避免在条件渲染中同时使用`AnimatePresence`
   - 统一模态框关闭的实现模式

2. **测试层面**
   - 增加更多边界情况的测试用例
   - 添加性能测试，监控DOM操作开销
   - 建立回归测试机制，防止类似问题再次出现

3. **流程层面**
   - 将E2E测试纳入CI/CD流程
   - 每次代码变更都自动执行E2E测试
   - 定期生成测试覆盖率报告
