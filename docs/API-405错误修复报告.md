# 浏览器控制台 405 错误修复报告

**问题编号**：API-405-001  
**问题描述**：浏览器控制台显示 59 个 405 错误  
**发现时间**：2026-05-19  
**严重程度**：中等  
**影响范围**：Supabase Edge Functions 和本地 Edge Functions 调用  

---

## 一、问题分析

### 1.1 错误描述

浏览器控制台出现大量错误信息：
```
Failed to load resource: the server responded with a status of 405 (Method Not Allowed)
```

### 1.2 错误数量统计

|-----|-----|
| 总错误数 | 59 |
| 错误类型 | HTTP 405 Method Not Allowed |

| 是否影响功能 | 否（核心功能正常） |

## 二、根本原因分析

### 2.1 Nginx CORS 配置限制

通过审查 Nginx 配置文件（`/www/wwwroot/ciond/nginx-full.conf`），发现两个关键位置存在 HTTP 方法限制：

#### 位置 1：`/supabase/functions/v1/`（第 39-64 行）

```nginx
location /supabase/functions/v1/ {
    if ($request_method = OPTIONS) {
        add_header Access-Control-Allow-Origin * always;
        add_header Access-Control-Allow-Methods "GET, POST, OPTIONS" always;  # ⚠️ 限制
        add_header Access-Control-Allow-Headers "authorization, x-client-info, apikey, content-type" always;
        add_header Access-Control-Max-Age 86400 always;
        return 204;
    }
    # ... 其他配置
}
```

**问题**：仅允许 `GET, POST, OPTIONS` 方法。

#### 位置 2：`/api/contract-convert/`（第 67-85 行）

```nginx
location /api/contract-convert/ {
    if ($request_method = OPTIONS) {
        add_header Access-Control-Allow-Origin * always;
        add_header Access-Control-Allow-Methods "GET, POST, OPTIONS" always;  # ⚠️ 限制
        add_header Access-Control-Allow-Headers "authorization, x-client-info, apikey, content-type, x-contract-convert-secret" always;
        add_header Access-Control-Max-Age 86400 always;
        return 204;
    }
    # ... 其他配置
}
```

**问题**：同样仅允许 `GET, POST, OPTIONS` 方法。

### 2.2 客户端请求方法分析

根据代码审查，系统中的 Supabase API 调用主要使用以下 HTTP 方法：

| 操作类型 | Supabase 方法 | 实际 HTTP 方法 | 是否被允许 |
|---------|--------------|----------------|----------|
| 查询数据 | `.select()` | GET | ✅ |
| 插入数据 | `.insert()` | POST | ✅ |
| 更新数据 | `.update()` | PATCH | ⚠️ 可能被限制 |
| 删除数据 | `.delete()` | DELETE | ⚠️ 可能被限制 |
| 文件上传 | Storage upload | POST | ✅ |

### 2.3 可能的问题场景

1. **Supabase Storage 预签名 URL 请求**
   - 使用 `createSignedUrl()` 可能发送 PUT 请求来生成签名
   - 如果 nginx 限制了 PUT 方法，会返回 405

2. **批量操作**
   - 某些 `.upsert()` 操作可能使用 PATCH 方法
   - 事务操作可能使用多种 HTTP 方法

3. **Edge Functions 调用**
   - 某些 Edge Functions 内部可能使用了不支持的 HTTP 方法

## 三、修复方案

### 3.1 方案一：扩展 Nginx HTTP 方法允许列表（推荐）

修改 Nginx 配置文件，添加对更多 HTTP 方法的支持：

```nginx
location /supabase/functions/v1/ {
    if ($request_method = OPTIONS) {
        add_header Access-Control-Allow-Origin * always;
        add_header Access-Control-Allow-Methods "GET, POST, PUT, PATCH, DELETE, OPTIONS" always;
        add_header Access-Control-Allow-Headers "authorization, x-client-info, apikey, content-type, x-contract-convert-secret" always;
        add_header Access-Control-Max-Age 86400 always;
        return 204;
    }
    # ... 其余配置保持不变
}

location /api/contract-convert/ {
    if ($request_method = OPTIONS) {
        add_header Access-Control-Allow-Origin * always;
        add_header Access-Control-Allow-Methods "GET, POST, PUT, PATCH, DELETE, OPTIONS" always;
        add_header Access-Control-Allow-Headers "authorization, x-client-info, apikey, content-type, x-contract-convert-secret" always;
        add_header Access-Control-Max-Age 86400 always;
        return 204;
    }
    # ... 其余配置保持不变
}
```

### 3.2 方案二：使用 IF 语句条件允许所有方法

```nginx
# 对于非 OPTIONS 请求，移除方法限制
set $cors_method "";
if ($request_method = 'GET') { set $cors_method "GET"; }
if ($request_method = 'POST') { set $cors_method "POST"; }
if ($request_method = 'PUT') { set $cors_method "PUT"; }
if ($request_method = 'PATCH') { set $cors_method "PATCH"; }
if ($request_method = 'DELETE') { set $cors_method "DELETE"; }
if ($request_method = 'OPTIONS') { set $cors_method "OPTIONS"; }
```

### 3.3 方案三：完全移除方法限制（生产环境谨慎使用）

```nginx
location /supabase/functions/v1/ {
    # 完全移除 limit_except 限制
    # 依赖后端服务（Supabase）来处理方法验证
}
```

